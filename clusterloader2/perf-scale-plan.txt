Pipeline
--------
- Orchestration lives in [helper-scripts/run-byocni-podstartup-multi.sh](helper-scripts/run-byocni-podstartup-multi.sh#L1); entry validates flags, assigns mesh/default scenarios, and drives per-run loops.
- Cluster lifecycle flows through [helper-scripts/byocni-cluster.sh](helper-scripts/byocni-cluster.sh#L1) which handles AKS create/update, mesh toggles, monitoring add-ons, and temp kubeconfig wiring.
- Each workload pass invokes [perf-tests/clusterloader2/run-podstartup.sh](perf-tests/clusterloader2/run-podstartup.sh#L1) to export the kubeconfig, stage CL2 variables, and call clusterloader2 with the desired config bundle.
- Pod churn logic is defined in [perf-tests/clusterloader2/podstartupanalysis/config.yaml](perf-tests/clusterloader2/podstartupanalysis/config.yaml#L1-L73); tuning sets, namespace counts, and throughput settings originate here.
- Optional overrides for pods-per-node, namespace count, and load/delete throughput flow via the new CLI flags and surface as CL2_* environment variables when the workload launches.
- Metrics modules load from [perf-tests/clusterloader2/measurements.yaml](perf-tests/clusterloader2/measurements.yaml#L1) and peers; optional Cilium/Kubelet collectors guard their own start/gather steps.
- Failures bubble back via non-zero exit codes: infra issues surface in the helper scripts, while workload regressions log under perf-tests/clusterloader2/logs within the podstartup run directory.
